# Как мы будем тестировать поселение (план)

Цель (Егор, 2026-10-06): проверять стройку и рост уже на самом поселении, быстро: на ускорении, чтобы люди появлялись сразу, караваны возвращались мгновенно и т.д. Все, что ниже, живет только в `f2mod_test.dat` и в релиз не входит.

## 1. Одно время для всех таймеров

В релизе поселение ничего не считает «в реальном времени». Все идет от игрового времени (`game_time`), а считается лениво: когда герой заходит в город или на карту мира, скрипт смотрит, сколько прошло с прошлого раза, и прокручивает недели одну за другой (доход, расходы, приток, мораль, стройки, караваны, события). Поэтому «ускорение» не надо изобретать: достаточно сдвинуть игровое время.

- Все сроки в скриптах задаем через одну функцию `dur(часы)`. В релизе она возвращает часы как есть. В тестовой сборке множитель переключается пультом: ×1, ×1/10, мгновенно (0).
- Сдвиг времени: пульт вызывает `game_time_advance`, затем сразу запускает «догоняющий» прогон. Герой стоит на месте, а у поселения проходит час, день, неделя, месяц.

## 2. Пульт отладки в поселении (только test)

Тестовый объект на карте (стол с терминалом у прораба, как «Строитель» в песочнице) и диалог с пунктами. Горячие клавиши остаются для самого частого (Ctrl+цифры).

| Раздел | Что делает |
|---|---|
| Время | +1 час, +1 день, +1 неделя, +1 месяц; множитель сроков ×1 / ×1/10 / мгновенно |
| Стройка | достроить все очереди сейчас; поставить любое здание на любой уровень (как в песочнице); бесплатно / за деньги (проверить цены) |
| Люди | +5 жителей, довести до N (15 / 45 / 80), раздать профессии автоматом, «приток прямо сейчас» |
| Караван | рейс завершить сейчас; вернуть мгновенно; потерять рейс (грабеж); поставить уровень каравана |
| Набег | вызвать сейчас: разведка / набег / роботы / мафия / Хорриган; с предупреждением и без |
| Ресурсы | деньги, еда, вода, патроны; обнулить; переполнить склад |
| Мораль и охрана | мораль 0-100, число охранников, уровень обучения |
| События и квесты | показать очередь событий, вызвать следующее, выставить стадию квеста, пометить выполненным |
| Сценарии | пакеты состояния: «старт», «через месяц», «этап 3 (45 жителей)», «все 3 уровня», «набег на пороге»; грузятся одним нажатием |
| Сброс | все в ноль, как на новой игре |

## 2а. Горячие клавиши (Егор, 2026-10-06: «а как упростить? хоткеями»)

Самое частое выносим на клавиши Alt+цифра (рядом с уже работающими Ctrl+цифры тестового набора; та же схема: перехват нажатия через sfall, результат строкой в окно сообщений). Пульт с диалогом остается для редкого и сложного.

| Клавиши | Действие |
|---|---|
| Alt+1 | +1 час |
| Alt+2 | +1 день |
| Alt+3 | +1 неделя |
| Alt+4 | +1 месяц |
| Alt+5 | множитель сроков: ×1 / ×1/10 / мгновенно по кругу |
| Alt+6 | достроить все стройки сейчас |
| Alt+7 | +5 жителей (Shift+Alt+7 довести до 45) |
| Alt+8 | караван вернуть сейчас |
| Alt+9 | вызвать набег (Shift+Alt+9 следующий вид набега) |
| Alt+0 | показать состояние: день, время, крышки, караван; с 0.4.0 вторая строка о лагере (посчитанная неделя, люди, еда и вода с приростом, касса, дух, недели нехватки, брошен ли); с 0.6.0 третья строка о набеге 1.3 и главаре (часов с основания, ушел ли герой, итог, частокол, ополченцы, спутник, состояние главаря) |
| Alt+Q | сценарий «через месяц», Alt+W «этап 3», Alt+E «все 3 уровня», Alt+R сброс |

## 3. Что видно на экране

Строка состояния в тесте (по клавише): день, жители, деньги, еда/вода, мораль, очередь строек (что и сколько осталось), ближайший караван и набег. Каждый недельный прогон пишет в журнал (`display_msg` и файл): что пришло, что ушло, кто родился, что построено. Так видно, откуда взялись числа.

## 4. Автопроверки

Команда «прогнать N недель» без остановки: поселение живет само, в конце печатается итог и проверки (например: деньги не ушли в минус без причины, еда/вода не скачут, приток не превышает лимит домов, караваны возвращаются). Сравниваем с таблицей экономики ([economy.md](economy.md)), а расхождения сразу видны.

## 5. Порядок работ

1. Часы и «ленивый» прогон недель (одна функция времени, `dur`).
2. Пульт со всем списком выше. Первыми: время, люди, караван, достроить стройки.
3. Хранение состояния в sfall-глобалах с понятными именами, чтобы сценарии могли их выставлять.
4. Сценарии и автопроверки.
5. Только потом сами системы (рост, экономика, караван, события) подключаем к часам. Каждая система сразу тестируется пультом.

Правила тест-режима: ничего из пульта не должно менять релизные файлы; тестовый множитель сроков по умолчанию 1, чтобы релиз вел себя как задумано.
